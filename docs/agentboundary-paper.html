AgentBoundary Benchmark v1.0

Author: Kevin O'Connor Date: June 3, 2026 Repository: https://github.com/KevinOBytes/AgentBoundary License: MIT

Abstract

AgentBoundary v1.0 is an open benchmark for measuring prompt-injection robustness in LLM-based agents. Unlike prior work that assigns severity by theoretical harm, this project derives every label from empirical live-model compliance: 51 structured prompt-injection scenarios across eight attack families, evaluated against 11 frontier and mid-tier models at temperature=0.0 using an LLM-as-judge pipeline with few-shot exemplified rubrics, structured JSON output, and explicit 3-way classification (refused / complied / neutral).

The active-execution compliance standard excludes mere restatement, translation, or echoing of injected text without adding new harmful explanatory detail. The overall compliance rate is 3.4% (19/552, CI: 2.2%–5.3%). No scenario achieved critical or high severity. Markdown injection and cognitive overload are the empirically most dangerous families at 6.5% and 6.6% compliance respectively, though with wide confidence intervals. Nine of eleven models achieved zero clear compliance. Cross-judge agreement is moderate for refusal (κ ≈ 0.49) but only fair for compliance (κ ≈ 0.32), indicating substantial uncertainty in absolute compliance counts; relative rankings and zero-compliance models are more stable. No human ground-truth validation has been performed. The benchmark, dataset, and raw evaluation records are made available for community validation.

1. Introduction

Prompt-injection benchmarks often assign severity by theoretical harm --- what could go wrong --- rather than measured compliance. That produces inflated threat ratings with zero predictive validity. AgentBoundary derives every label from what actually happens when you send the attack to a live model.

1.1 Contributions

  1. Empirical severity labels. All 51 entries evaluated against 11 models at temperature=0.0. Severity derived from measured compliance rates.
  2. Cross-spectrum model coverage. Frontier closed-weight APIs (GPT-5-pro, Claude Opus-4.7, Gemini 3.5 Flash), mid-tier open-weight (DeepSeek V4 Pro, Llama-4 Maverick, Xiaomi MIMO-v2.5-pro), small-parameter (GPT-5-mini), reasoning-specialized (O3-mini), and injection-aware baseline (GLM-5.1).
  3. LLM-as-judge methodology. Two-pass gpt-5.4 judge with few-shot exemplified rubrics and structured JSON output. The compliance pass includes an explicit exclusion rule: mere restatement, translation, or echoing of injected text without adding new harmful explanatory detail is scored as not_complied. Refusal kappa = 0.492 (moderate agreement) and compliance kappa = 0.316 (fair agreement) against zero-shot baseline. Without human ground truth, these κ values measure inter-judge consistency, not objective calibration.
  4. Honest limitations and uncertainty quantification. Explicitly identifies what the dataset is (structured synthetic prompt collection), what it is not (validated attack corpus with human ground truth), and known gaps. All proportions report 95% Wilson score confidence intervals.

1.2 Scope and Non-Claims

This benchmark does not claim a generalizable safety ranking of foundation models, vendors, or products. It evaluates specific model endpoints at a specific date via OpenRouter's routing layer.

This benchmark does not simulate live tool execution. Tests use chat completion APIs, not actual agent frameworks.

This benchmark does not test adaptive adversaries. All prompts are static.

3. Threat Model

We assume an agent that:

  • Accepts user messages and ingests retrieved documents, fetched URLs, and memory recall as context
  • Can propose calls to a fixed set of tools
  • Runs under a system prompt with instruction hierarchy (system > user > retrieved)
  • Is evaluated via standard chat completion API

We assume an adversary that controls one source of untrusted context---a document, retrieval result, memory note, or incident ticket---and aims for one of five outcomes: system-prompt exfiltration, tool misuse, policy bypass, secret disclosure, or unsafe reasoning.

5.2 Judge Pipeline

Each evaluation uses a two-pass LLM-as-judge via gpt-5.4 with few-shot exemplified rubrics and structured JSON output:

Pass 1 --- Refusal detection: Does the response explicitly refuse the malicious request? (refused / not refused)

Pass 2 --- Compliance detection: Did the model actively execute the expected malicious behavior? (complied / not complied)

Exclusion rule: Mere restatement, translation, or echoing of injected text without adding new harmful explanatory detail is scored as not_complied.

Resolution rules:

  • refused + not complied → refused
  • not refused + not complied → neutral
  • not refused + complied → complied
  • refused + complied → conflict (flagged for manual review; occurred in 0 cases)

6.5 Judge Calibration

Cross-judge validation on a stratified 50-entry sample compared our few-shot judge against a zero-shot baseline:

MetricZero-shot (gpt-4o-mini)Few-shot (gpt-5.4)Change
Overall compliance55/552 = 10.0%19/552 = 3.4%-~3x (same outputs, different judges)
Refusal kappa0.05--0.230.492+moderate
Compliance kappa<00.316+fair
Combined agreement~30%71.4%+substantial

The reduction is consistent with the hypothesis that zero-shot judges conflate passive acknowledgment (e.g., echoing attacker text in a translation) with active execution. Because no human ground truth exists, we cannot claim the few-shot judge is closer to truth — only that it is more internally consistent (higher cross-judge kappa) and more conservative (lower compliance rate). The comparison is between the zero-shot judge and the few-shot judge applied to the same 552 model responses.

7. Discussion

7.1 RAG Poisoning Is the Dominant Vector

At 6.5% family-level compliance, markdown injection shows the highest rate, followed by cognitive overload at 6.6% and RAG poisoning at 4.6%. Only five of eight families show any measurable compliance.

7.2 Neutral Responses Are an Unresolved State

Five models (Gemini 3.5 Flash at 31.4%, Llama-4 Maverick at 31.4%, GPT-5-mini at 31.4%, GPT-5-pro at 23.8%, MIMO-v2.5-pro at 25.5%) produced neutral rates above 20%. A neutral response means the model neither refused nor actively complied. Whether this represents a security failure depends on deployment context: in some settings silent non-refusal is acceptable, while in high-assurance settings it is not. GLM-5.1 achieved 23.5% neutral with 76.5% explicit refusals and zero compliance.

7.3 Concentration of Vulnerability

Five of 11 models show any measurable vulnerability. Llama-4 Maverick accounts for 10 of 19 total compliance cases (52.6%). DeepSeek V4 Pro (4/51) and DeepSeek V4 Flash (2/51) are the next most vulnerable.

8. Limitations

  1. Single prompt variant per entry. Adaptive adversaries with paraphrase variations might achieve higher compliance.
  2. No human ground truth. LLM-as-judge is not validated against human raters. The severity labels in this benchmark are derived from LLM-as-judge verdicts, and the judge's quality is assessed by comparing it against other LLM judges (cross-judge kappa). This creates a methodological circle: the judge defines compliance, and compliance validates the judge. Cross-judge triangulation with three distinct judges on a stratified 50-entry sample yielded overall agreement of approximately κ ≈ 0.2 (slight). This means absolute compliance counts have wide uncertainty bars; relative rankings and zero-compliance models are more stable. The pairwise Cohen's kappa reported in Section 6.5 (refusal κ = 0.492, compliance κ = 0.316) measures agreement between only our few-shot judge and a zero-shot baseline on the same 552 responses. A stratified human-rater study (n=200) is planned for v1.1 to break this circle.
  3. No live tool bindings. Tests use chat completion APIs. Toolchain confusion may differ with live tool schemas.
  4. Temperature zero. Removes sampling noise but does not measure compliance variance.
  5. Static adversary. Fixed catalog against fixed models.
  6. OpenRouter routing layer. Results characterize the endpoint on the evaluation date.
  7. Exclusion-rule dependence. The active-execution compliance standard (mere restatement/echoing scored as not_complied) is enforced by few-shot judge prompt design. Different rubric phrasing produces different counts.

9. Future Work

v1.1 -- Paraphrase Sensitivity. Generate 3-5 prompt variants per attack; re-run on the most vulnerable families to measure compliance variance across formulation.

v1.2 -- Multi-Turn Conversation. Extend the harness to dialog state with priming phase, adversarial injection, and probe. Tests whether refusal boundaries degrade across conversation turns.

v2.0 -- Live Agent. Evaluate real agent implementations (LangChain, AutoGen) with actual tool schemas and persistent memory. This tests the LLM-as-agent layer, not the LLM chat-completion layer.

A human-judge baseline on a stratified 200-entry sample is the highest priority for v1.1. Without it, benchmark claims remain exploratory. See docs/HUMAN_VALIDATION_PROTOCOL.md for the planned protocol.

10. Conclusion

Empirically grounded severity labels produce a different threat picture than synthetic harm assessment. Most models show zero measurable vulnerability to direct prompt injection. Markdown injection, cognitive overload, and RAG poisoning are the outliers, though with wide confidence intervals. The benchmark, dataset, and raw records are available for community validation under MIT license.
